# فالینو ✨ | Falino — نسخه ۲

**«یه قرار کوچولو با ستاره‌ها، هر روز کنار تو 💛»**

ربات چندزبانه فال و طالع‌بینی با پایه **Telethon**، پنل مدیریت داخل تلگرام و SQLite. دریافت رویدادها فقط با Telethon است؛ پیام‌های دارای رنگ دکمه از Bot API ارسال می‌شوند. مرورگر، Redis و پنل وب جدا لازم نیست.

نام نمایشی انتخاب‌شده: **Falino | فالینو ✨**. آزادبودن نام کاربری تلگرام یا انحصاری‌بودن نام تجاری ادعا نشده است.

## امکانات برای کاربران

منظور از «زبان اسرائیلی»، عبری در نظر گرفته شده است. همه منوها، راهنما، جریان پشتیبانی، حریم خصوصی و عنوان برج‌ها در این زبان‌ها همراه کد هستند. در اولین `/start`، پیش از منوی اصلی، شرط عضویت و دریافت فال، کاربر باید زبان را انتخاب کند؛ زبان به صورت خودکار از تلگرام تعیین نمی‌شود. انتخاب ذخیره‌شده حفظ می‌شود و با `/language` قابل تغییر است؛ شکل‌هایی مانند `zh-hans`، `hi-IN` و کد قدیمی `iw` نیز شناخته می‌شوند. پنل مدیریت فارسی است.

**مهم درباره متن فال:** منبع فال انگلیسی است. برای ترجمه خودکار باید سرویس ترجمه سازگار تنظیم شود. بدون کلید ترجمه، رابط ده‌زبانه کار می‌کند و فال انگلیسی با توضیح به زبان کاربر نمایش داده می‌شود؛ ترجمه آماده و ناموجود ادعا نشده است. نام برخی کارت‌ها و سیارات نام‌های انگلیسی منبع هستند.

## پنل مدیر

ورود: `/panel`؛ فقط شناسه‌های عددی `ADMIN_IDS` اجازه دارند.

- آمار روزانه، هفتگی، ماهانه و کلی.
- پرونده کاربر، جست‌وجو با شناسه/نام/نام کاربری، فعالیت و فال‌های اخیر، محدود/آزادکردن حساب.
- صندوق تیکت‌ها و پاسخ خصوصی، گروه خصوصی پاسخ‌گویی و یادداشت داخلی.
- گروه خصوصی لاگ با مشخصات کاربر و نوع فال دریافتی.
- عضویت اجباری چندکاناله با هدف جذب یا هدف تعداد کل اعضا.
- برنامه‌های انتشار کانال، پیش‌نمایش، توقف، فعال‌سازی و حذف.
- آمار کمپین‌ها، لینک معرفی، پیام همگانی با پیش‌نمایش و تأیید.
- رنگ مجاز دکمه، ایموجی سفارشی، متن شروع، عنوان دکمه و امضای کانال.
- وضعیت صف ارسال و تعداد تیکت باز.

### تعریف آمار

| گزارش | بازه |
|---|---|
| روزانه | از ساعت ۰۰:۰۰ امروز به وقت تهران |
| هفتگی | از ساعت ۰۰:۰۰ شنبه همین هفته به وقت تهران |
| ماهانه | از روز اول ماه شمسی جاری به وقت تهران |
| کلی | همه داده‌های ثبت‌شده از آغاز پایش |

گزارش شامل تعداد ثبت‌نام، کاربر فعال **یکتا**، دریافت موفق فال به تفکیک نوع، پیام پشتیبانی، پاسخ مدیر، معرفی تأییدشده، نوبت موفق کانال و خطاست. مجموع کاربران، دریافت‌کنندگان روزانه، محدودشدگان و مسدودکنندگان ربات نیز به صورت وضعیت فعلی نمایش داده می‌شوند.

هر درخواست موفق، حتی اگر متن از کش آمده باشد، یک دریافت محسوب می‌شود. دریافت از تاریخچه با مسیر `history` ثبت می‌شود؛ ارسال خودکار با مسیر `scheduled`. تلاش ناموفق، دریافت موفق شمرده نمی‌شود. بازخورد و منبع ورودی از رکوردهای فعلی نشان داده می‌شوند. روز و هفته آماری مدیر بر مبنای تهران‌اند؛ ساعت ارسال خصوصی بر مبنای منطقه انتخابی هر کاربر است.

در ارتقا از نسخه قبل، تاریخ ثبت‌نام‌های موجود بازیابی می‌شود؛ آمار تاریخی فال و فعالیتی که قبلاً ثبت نشده، ساخته نمی‌شود. زمان شروع ثبت جزئیات در انتهای گزارش دیده می‌شود. حذف پروفایل، آمار تجمیعی بدون نام را پاک نمی‌کند؛ تعداد فعال یکتا مربوط به پروفایل‌هایی است که هنوز نگهداری می‌شوند.

## نصب با Docker

کد آماده اجراست؛ ورود واقعی به تلگرام نیاز به اطلاعات خودت و یک سرور دائمی دارد.

```bash
cp .env.example .env
chmod 600 .env
```

فایل `.env` را تکمیل کن:

```dotenv
API_ID=123456
API_HASH=your_telegram_api_hash
BOT_TOKEN=123456789:your_bot_token
ADMIN_IDS=123456789
```

- توکن: [BotFather](https://t.me/BotFather) ← `/newbot`.
- API ID و API Hash: [my.telegram.org](https://my.telegram.org) ← API development tools؛ برای ربات Telethon هم لازم‌اند.
- ADMIN_IDS: شناسه عددی مدیران، جداشده با کاما؛ `@username` کافی نیست.
- مقدارهای واقعی را در مخزن عمومی قرار نده.

```bash
docker compose up -d --build
docker compose logs -f --tail=100
```

با حساب مدیر، خصوصی ربات `/start` و سپس `/panel` را بزن. توصیف و منوی فرمان‌ها در ده زبان هنگام راه‌اندازی اولیه تنظیم می‌شوند؛ برای نمایش آن‌ها کلاینت تلگرام ممکن است به بازکردن مجدد صفحه ربات نیاز داشته باشد.

پوشه برنامه همچنان `astra_bot` و ماژول اجرا `astrobot` است تا نصب قبلی بدون تغییر مسیر کار کند. داده و session در volume دائمی `astra-data` می‌مانند. `docker compose down` داده را نگه می‌دارد؛ `down -v` آن را حذف می‌کند. فقط یک نمونه برنامه برای یک دیتابیس و توکن اجرا کن.

### اجرای مستقیم روی Linux

Python 3.12:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m astrobot
```

نمونه سرویس دائمی در `deploy/astra.service` است. مسیر سازگار با نسخه قبل `/opt/astra_bot`، کاربر سیستم `astra` و مسیر داده سرویس `/var/lib/astra` است. فایل `.env` را قبل از اجرا تکمیل کن.

```bash
sudo useradd --system --home /opt/astra_bot --shell /usr/sbin/nologin astra
sudo chown -R astra:astra /opt/astra_bot
sudo cp deploy/astra.service /etc/systemd/system/astra.service
sudo systemctl daemon-reload
sudo systemctl enable --now astra
sudo journalctl -u astra -f
```

برای Windows، Docker مناسب‌تر است. سرور باید به Telegram MTProto، `api.telegram.org` و `www.freehoroscopeapi.com` دسترسی داشته باشد. پراکسی HTTP و Telethon در `.env` جدا تنظیم می‌شوند.

```dotenv
LLM_BASE_URL=https://your-provider.example/v1

```

## گروه لاگ و پرونده کامل کاربر

۱. یک **گروه خصوصی تیم مدیریت** بساز و ربات را ادمین کن.

۲. با حسابی که در ADMIN_IDS است داخل گروه `/chatid` را بزن.

۳. پنل ← گروه لاگ؛ شناسه منفی گروه را وارد کن. حذف اتصال: `off`.

لاگ شامل نام و نام خانوادگی دریافتی، نام کاربری، شناسه قابل کلیک، زبان تلگرام و ربات، وضعیت پرمیوم اعلام‌شده، نام دلخواه، تولد ثبت‌شده، برج، ساعت دریافت، زمان ورود و آخرین فعالیت، امتیاز و زنجیره، معرف و منبع، وضعیت محدودیت و **نوع فال و برج انتخاب‌شده** است. مشخصات در زمان همان رخداد ثبت می‌شوند؛ تغییر بعدی پروفایل، لاگ قبلی را بازنویسی نمی‌کند.

ربات شماره تلفن، IP، فهرست مخاطبان، سایر گروه‌های کاربر یا گفت‌وگوهای خصوصی او را نمی‌بیند. «مشخصات کامل» یعنی فیلدهای در دسترس ربات و اطلاعاتی که کاربر خودش وارد کرده است. نمونه `/user 123456789` در خصوصی مدیر، پرونده همان کاربر را باز می‌کند؛ از پنل هم می‌توان نام یا `@username` را جست‌وجو کرد.

اطلاع ثبت داده و `/privacy` در تجربه کاربر وجود دارد. گروه عمومی برای این کاربرد پذیرفته نمی‌شود. انتخاب اعضای قابل اعتماد گروه مسئولیت مدیر ربات است.

لاگ و پشتیبانی صف ماندگار دارند. تیکت‌ها در صف اولویت دارند. ارسال گروه با فاصله محافظه‌کارانه انجام می‌شود؛ رسیدن فوری تمام لاگ‌ها در ترافیک زیاد تضمین نمی‌شود. صف لاگ حداکثر ۵۰۰۰ مورد است؛ جزئیات رخدادها مستقل از آن در دیتابیس ۹۰ روز نگه داشته می‌شوند. صف‌های خطادار تا ۱۰ تلاش و حداکثر یک هفته نگهداری می‌شوند.

## پشتیبانی دوطرفه

کاربر `/support` را می‌زند و پیامش را می‌فرستد. عکس، ویس و فایل بدون دانلود روی سرور با Telegram copy منتقل می‌شوند. شماره تیکت به او داده می‌شود. برای ادامه گفتگو، دوباره «ارتباط با تیم» یا `/support` را می‌زند؛ تا وقتی تیکت باز است، پیام به همان تیکت افزوده می‌شود.

پنل ← گروه پاسخ‌گویی؛ شناسه یک گروه خصوصی را تنظیم کن. اگر گروهی تنظیم نباشد، تیکت به خصوصی مدیران ADMIN_IDS فرستاده می‌شود. مدیر باید قبلاً ربات را استارت کرده باشد.

مدیر می‌تواند:

```text
روی پیام تیکت Reply کند و پاسخ را بنویسد یا فایل بفرستد.
/reply 42 سلام، خوشحالیم پیام دادی...
/ticket 42
/close 42
```

- `/reply` و پاسخ مستقیم فقط از حساب‌های ADMIN_IDS و در گروه پشتیبانی تنظیم‌شده یا خصوصی همان مدیر پذیرفته می‌شود.
- بازکردن تیکت از پنل و دکمه «پاسخ» هم ممکن است.
- برای یادداشت داخلی، در Reply بنویس: `!note توضیح داخلی`؛ این متن برای کاربر ارسال نمی‌شود.
- `/tickets` و دکمه قفل، مشاهده و بستن تیکت خود کاربر را ممکن می‌کنند؛ تیکت شخص دیگری قابل مشاهده نیست.
- پشتیبانی، حریم خصوصی و توقف/حذف داده پشت دیوار عضویت قفل نمی‌شوند.
- هر کاربر تا ۱۰ پیام پشتیبانی در ساعت می‌تواند ثبت کند.
- ویرایش خودکار پیام‌های قدیمی، تماس صوتی زنده، ترجمه خودکار گفت‌وگوی مدیر و forum-topic جدا برای هر تیکت در این نسخه نیست؛ مسیر پاسخ روی شناسه پیام و تیکت ثبت می‌شود.

## عضویت اجباری با هدف

ربات را در کانال ادمین کن. پنل ← عضویت اجباری. هر کانال در یک خط؛ فهرست جدید جایگزین قبلی می‌شود.

بدون سقف:

```text
@YourChannel | https://t.me/YourChannel
```

تا رسیدن **کل اعضای کانال به ۵۰۰۰ نفر**:

```text
@YourChannel | https://t.me/YourChannel | members | 5000
```

تا جذب **۱۰۰ حساب جدید تأییدشده از مسیر ربات**:

```text
@YourChannel | https://t.me/YourChannel | joins | 100
```

کانال خصوصی:

```text
-1001234567890 | https://t.me/+YourActualInvite | joins | 100
```

- با رسیدن به هدف، فقط شرط همان کانال برداشته می‌شود؛ بقیه کانال‌های اجباری مستقل‌اند.
- در حالت `members` شمار کل اعضا از تلگرام گرفته و حداکثر یک بار در دقیقه تازه می‌شود. خطای شمارش، شرط را خودسرانه غیرفعال نمی‌کند.
- در حالت `joins` باید ربات ابتدا عضو‌نبودن آن حساب را دیده باشد و سپس عضو‌شدنش را تأیید کند. عضوهای قبلی و بررسی‌های تکراری حساب نمی‌شوند.
- هر حساب در هر کمپین هدف فقط یک بار شمرده می‌شود؛ خروج و ورود مجدد یا حذف/ساخت دوباره پروفایل ربات امتیاز جذب تازه نمی‌دهد.
- هدف جذب، مجموع حساب‌های جدید تأییدشده است، نه تضمین انسان‌های متمایز یا تعداد اعضای خالص باقی‌مانده بعد از خروج افراد.
- هدفی که کامل شد دوباره فعال نمی‌شود؛ برای کمپین تازه هدف یا نوع را تغییر بده. ثبت دوباره همان کانال/نوع/عدد، پیشرفت قبلی را حفظ می‌کند.
- سقف ۱۰ کانال است. برای حذف همه شرط‌ها `off` بفرست.
- در کانال خصوصی، درست‌بودن لینک دعوت متعلق به همان کانال را خودت بررسی کن؛ عضویت با شناسه کانال سنجیده می‌شود.

## برنامه انتشار کانال

ربات باید ادمین کانال و دارای مجوز Post Messages باشد.

```text
@YourChannel | 6 | general | fa | all | 09:00 | Asia/Tehran
```

ترتیب:

```text
کانال | فاصله به ساعت | نوع محتوا | زبان | برج | ساعت اولین نوبت | منطقه زمانی
```

| فیلد | مقدار مجاز |
|---|---|
| فاصله | عدد صحیح ۱ تا ۸۷۶۰ ساعت |
| نوع | `general`, `daily`, `weekly`, `monthly`, `yearly`, `tarot` |
| زبان | یکی از ده کد جدول بالا |
| برج | `all` یا `aries taurus gemini cancer leo virgo libra scorpio sagittarius capricorn aquarius pisces` |
| ساعت | ۲۴ساعته؛ مانند `09:00` |
| منطقه | نام IANA مانند `Asia/Tehran`، `Asia/Shanghai` یا `Asia/Kolkata` |

`general` خلاصه واقعی ۱۲ برج است؛ فال عمومی ساختگی برای همه نیست. `all` در فال کامل، متن همه برج‌ها را جدا می‌فرستد. برای general و tarot فیلد برج نادیده گرفته می‌شود.

اولین ارسال در **نوبت بعدی ساعت انتخابی** است. فاصله‌های بعدی ساعت ثابت‌اند؛ در مناطقی با تغییر ساعت تابستانی، ساعت دیواری ممکن است جابه‌جا شود. از پنل می‌توان پیش‌نمایش خصوصی گرفت و برنامه را متوقف، فعال یا حذف کرد. فعال‌سازی دوباره، نوبت را به اندازه فاصله انتخابی از اکنون جلو می‌برد. برای تغییر ساعت/نوع، برنامه قبلی را حذف و دوباره بساز.

در خاموشی طولانی، نوبت‌های ازدست‌رفته پشت سر هم ارسال نمی‌شوند. ارسال چندبخشی از بخش تکمیل‌نشده ادامه پیدا می‌کند. خطای منبع باعث تأخیر و تلاش دوباره می‌شود؛ خطای دسترسی ۴۰۰/۴۰۳ کانال برنامه را متوقف می‌کند تا مدیر دسترسی را اصلاح کند.

## جذب و بازگشت کاربر

ستاره‌ها **امتیاز رایگان داخلی** هستند و ارزش پولی ندارند:

- دریافت روزانه جایزه: ۵ ستاره، یک بار در روز UTC؛ تغییر منطقه زمانی جایزه تازه نمی‌سازد.
- چالش روزانه: دریافت فال روز + ثبت حال امروز → ۱۰ ستاره با درخواست کاربر.
- چالش هفتگی: حضور در سه روز هفته آماری → ۲۰ ستاره، یک بار در هفته.
- دعوت تأییدشده: تکمیل تاریخ تولد دوست و دریافت اولین فال روزانه → ۳۰ ستاره برای معرف؛ یک بار برای هر حساب.
- زنجیره حضور و رکورد از بازدیدهای روزانه ساخته می‌شود؛ حضور، امتیاز روزانه را خودکار برداشت نمی‌کند.
- کلکسیون از کارت‌های واقعی تاروت روز که با موفقیت دریافت شده‌اند ساخته می‌شود.
- تبریک تولد بخشی از ارسال روزانه فعال است؛ برای افراد بدون اشتراک روزانه پیام ناخواسته جدا فرستاده نمی‌شود. سالگرد تولد شمسی با تقویم شمسی سنجیده می‌شود؛ روز کبیسه در سال غیرکبیسه به آخرین روز همان ماه می‌رسد.

لینک دعوت از `/ref` می‌آید. کمپین‌ها در پنل با قالب زیر ساخته می‌شوند:

```text
instagram | اینستاگرام
```

خروجی مانند `https://t.me/YourBot?start=src_instagram` است. معرف و منبع فقط در اولین ثبت پروفایل تعیین می‌شوند و با استارت دوباره عوض نمی‌شوند. رشد واقعی به کیفیت محتوا، جامعه هدف و معرفی ربات بستگی دارد؛ این امکانات تضمین عدد مشخصی جذب نیستند.

## ظاهر و متن

- رنگ دکمه: آبی `primary`، سبز `success`، قرمز `danger` یا پیش‌فرض تلگرام؛ رنگ دلخواه HEX و رنگ مستقل متن دکمه در اختیار ربات نیست.
- ایموجی سفارشی: شناسه عددی custom emoji را در پنل وارد کن؛ حذف با `off`. شرایط مجوز پرمیوم/Fragment تلگرام و نوع گفتگو تعیین می‌کند که واقعاً نمایش داده شود یا نه. در خطای پشتیبانی‌نشدن تزئینات، پیام ساده امتحان می‌شود.
- متن دکمه، نمونه: `fa | daily | 🔮 فال امروز من`. برای برگشت عنوان اصلی: `fa | daily | reset`.
- متن شروع: `fa | سلام رفیق! به فالینو خوش اومدی 💛`.
- محدودیت‌ها: شروع ۵۰۰ حرف، عنوان دکمه ۶۴ حرف، امضای کانال ۱۰۰ حرف. متن‌های مدیر ساده‌اند و HTML اجرا نمی‌کنند.
- عنوان‌های اصلی قابل ویرایش: `daily weekly monthly yearly birth profile language tarot schedule subscribe back check history favorites rewards quests collection spread partners support tickets explore faq privacy`.
- نشان برداری در `assets/falino-mark.svg` و تصویر آماده پروفایل در `assets/falino-avatar.png` قرار دارد؛ بارگذاری تصویر در تلگرام خودکار انجام نشده است.

## فال سالانه و محدودیت منبع

سرویس FreeHoroscopeAPI فقط متن روز، هفته و ماه جاری را می‌دهد. برای سالانه، مدیر متن را منتشر می‌کند:

```text
2026 | aries | fa | متن فال سالانه این برج...
```

سال، **سال میلادی مقصد** است؛ نه سال تولد کاربر. برای هر برج و زبان جدا ثبت می‌شود؛ ثبت دوباره همان کلید جایگزین متن است. تا قبل از انتشار، ربات نبود محتوا را اعلام می‌کند. هیچ متن ساختگی به API نسبت داده نمی‌شود.

- فال روزانه منبع به برج وابسته است؛ افراد هم‌برج متن یکسان می‌گیرند. تحلیل روزانه منحصربه‌فرد بر اساس سال تولد وجود ندارد.
- تاریخ منبع همیشه نمایش داده می‌شود؛ API تازگی متن را تضمین نمی‌کند. تفاوت تاریخ روزانه با امروز UTC توضیح داده می‌شود.
- دیروز، فردا و تاریخ دلخواه برای متن فال توسط این API پشتیبانی نمی‌شوند.
- `/natal` موقعیت زمین‌مرکزی سیارات در زودیاک استوایی را از API محاسباتی می‌گیرد؛ بازه ۱۹۰۰ تا پیش از ۲۰۵۳. خانه‌ها و طالع یا تفسیر چارت کامل ندارد.
- `/moon` فاز تقریبی از چرخه متوسط را می‌دهد؛ تقویم رصدی دقیق یا طلوع/غروب نیست.
- سازگاری، مقایسه تفننی عناصر سنتی است؛ پیش‌بینی رابطه نیست.
- تفسیر کارت‌ها عین داده منبع یا ترجمه آن‌هاست؛ ورودی سؤال شخصی یا تعبیر خواب هوشمند در این نسخه نیست.
- اشتراک پولی، فروش Stars، درگاه مالی، اشتراک پریمیوم تجاری و مینی‌اپ جدا پیاده نشده‌اند.

## ارتقا از نسخه قبل

۱. از دیتابیس و تنظیمات بکاپ بگیر.

۲. برنامه را متوقف کن و کد جدید را در همان پوشه جایگزین کن؛ `.env` و داده را نگه دار.

۳. اجرا کن؛ ستون‌ها و جدول‌های تازه خودکار و بدون حذف کاربران ساخته می‌شوند.

```bash
docker compose up -d --build
```

نام package، فایل `astra.sqlite3`، volume و مسیر سرویس عمداً برای سازگاری تغییر نکرده‌اند. مهاجرت رو به جلو است؛ برای برگشت به نسخه قبلی، snapshot پیش از ارتقا را بازیابی کن. تقویم سالگرد تولد کاربران قدیمی که نوع تقویمشان قبلاً ذخیره نشده، پیش‌فرض میلادی است؛ با ثبت دوباره تاریخ تولد می‌توانند شمسی را انتخاب کنند.

## داده، نگهداری و مصرف

- یک پردازش async، WAL و indexهای صف/سررسید؛ بدون ساخت task دائمی برای هر کاربر.
- کش اشتراکی فال یک ساعت و ترجمه ۳۰ روز؛ حداکثر سه درخواست هم‌زمان سرویس محتوا.
- تاریخچه هر کاربر محدود به ۳۰ ورودی اخیر و حداکثر ۲۰ محبوب است؛ snapshot هر فال حداکثر ۲۴ هزار نویسه در بخش‌های کامل پیام دارد.
- رخداد دقیق ۹۰ روز، مسیر پیام‌های گروه ۳۰ روز و شمارنده‌های تجمیعی ماندگارند. پس از پاک‌سازی، فایل SQLite الزاماً فوراً کوچک نمی‌شود؛ برای کاهش فیزیکی حجم در زمان نگهداری از ابزار استاندارد SQLite استفاده کن.
- `/delete_me` پروفایل و داده شخصی محلی را حذف می‌کند؛ حذف نسخه‌های شناخته‌شده گروه درخواست می‌شود. محدودیت حذف پیام تلگرام، دسترسی ربات، کپی دیگران و بکاپ‌های قدیمی ممکن است مانع پاک‌شدن کامل نسخه بیرونی شوند.
- شمارنده‌های بدون نام و fingerprint کلیددار ضد تکرار باقی می‌مانند؛ نام یا شناسه خام داخل fingerprint نیست. این موضوع در متن حریم خصوصی همه زبان‌ها آمده است.
- داده محلی رمزگذاری کاربردی ندارد؛ سرور، گروه‌های تیم و بکاپ باید فقط در دسترس افراد مورد اعتماد باشند.
- لاگ عملیاتی سرور توکن، تاریخ تولد و متن خصوصی کاربران را چاپ نمی‌کند. اطلاعات مدیریتی درخواست‌شده فقط در دیتابیس و گروه خصوصی تنظیم‌شده قرار می‌گیرد.
- در فاصله کوتاه میان تحویل تلگرام و ثبت نتیجه، قطع ناگهانی می‌تواند تکرار ایجاد کند؛ تضمین exactly-once ادعا نمی‌شود.
- طراحی کم‌مصرف است، اما ظرفیت تولیدی و RAM در بار واقعی بدون تست روی سرور شما تضمین نشده است.

## تست و بررسی نهایی

```bash
pip install -r requirements-dev.txt
python -m pytest -q
ruff check astrobot tests backup.py smoke_api.py benchmark.py
python -m compileall -q astrobot
python smoke_api.py
```

تست‌ها بدون حساب تلگرام اجرا می‌شوند. `smoke_api.py` فقط سرویس محتوا را واقعاً صدا می‌زند. گزارش نتیجه در `VALIDATION.md` است. برای نمونه‌گیری محلی بدون شبکه می‌توان `python benchmark.py --users 1000` را اجرا کرد؛ این بنچمارک جای تست ظرفیت سرور واقعی نیست.

برای تست حساب واقعی: با مدیر و کاربر عادی `/panel` را امتحان کن؛ هر دو هدف عضویت را در کانال تست بررسی کن؛ یک تیکت متنی و ویس بفرست و از گروه پاسخ بده؛ به عنوان کاربر دیگر تلاش کن تاریخچه را باز کنی؛ ده زبان و برنامه انتشار آزمایشی را بررسی کن. ورود تلگرام، مجوز کانال، نمایش پرمیوم و ساخت تصویر Docker بدون اطلاعات و محیط واقعی قابل تأیید نبوده‌اند.

## پشتیبان‌گیری

```bash
python backup.py --data-dir data --output backups
```

این ابزار snapshot سازگار SQLite می‌سازد؛ `.env` و session بکاپ امن جدا می‌خواهند. بکاپ باید از سرور هم به محل امن دیگری منتقل شود. برای کپی مستقیم volume، برنامه را متوقف کن؛ فایل‌های WAL/SHM را خودسرانه جا نگذار. برای بازیابی، برنامه متوقف باشد و snapshot با فایل‌های WAL/SHM قدیمی دیتابیس قبلی ترکیب نشود.
